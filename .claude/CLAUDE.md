# Bitwarden Secrets Manager Kubernetes Operator

Go operator built with Operator SDK and Kubebuilder. It registers a `BitwardenSecret` Custom Resource Definition and runs a controller that syncs the secrets a Secrets Manager machine account can access into a Kubernetes Secret, on a configurable refresh interval.

[README.md](../README.md) is the main reference for setup, configuration, the `BitwardenSecret` spec and manual testing. Read the relevant section there instead of guessing. General contribution guidelines are linked from [CONTRIBUTING.md](../CONTRIBUTING.md).

## Key paths

- `api/v1/bitwardensecret_types.go`: CRD types and `+kubebuilder:` markers.
- `api/v1/zz_generated.deepcopy.go`: generated by `make generate`. Do not edit by hand.
- `internal/controller/bitwardensecret_controller.go`: the reconcile loop, plus `+kubebuilder:rbac` markers.
- `internal/controller/test/`: controller tests and mocks.
- `cmd/main.go`: operator entry point.
- `config/`: kustomize manifests. `config/crd/bases/` and `config/rbac/role.yaml` are generated by `make manifests`.
- `config/samples/k8s_v1_bitwardensecret.yaml`: sample `BitwardenSecret`.
- `.devcontainer/`: the Dev Container definition and its setup script.

## Development environment

The README strongly recommends the VS Code Dev Container, especially on macOS and Windows. It needs VS Code, Docker (Podman is not supported by the Dev Container) and the Dev Containers extension, and VS Code must be opened at the repository root.

On creation, `.devcontainer/postCreateCommand.sh` installs `kubectl` and `musl-tools`, recreates a kind cluster named `sm-operator`, then runs `make setup` and `make install`.

- The `build`, `run` and `test` targets compile with `CC=musl-gcc` and static linking. The README lists `musl-gcc` only for manual Linux setups, so on other hosts expect these targets to work only inside the Dev Container.
- `make setup` copies `.env.example` to `.env` if it does not exist. The variables are documented under "Configuration settings" in the README. `.env` is gitignored.
- The operator, `make install`, `make uninstall`, `make deploy` and `make undeploy` all act on the current kubeconfig context.
- The VS Code debugger does not work if the workspace is opened through a symlink. Open it from the full path.

## Commands

All targets are defined in the `Makefile`; run `make help` for the full list.

| Command                                 | What it does                                                                                   |
| --------------------------------------- | ---------------------------------------------------------------------------------------------- |
| `make setup`                            | Create `.env` from `.env.example`                                                              |
| `make manifests`                        | Regenerate CRD and ClusterRole from markers                                                    |
| `make generate`                         | Regenerate DeepCopy methods                                                                    |
| `make fmt` / `make vet`                 | `go fmt ./...` / `go vet ./...`                                                                |
| `make test`                             | Runs `manifests generate fmt vet` first, then the envtest-backed `go test ./...` with coverage |
| `make build`                            | Build `bin/manager`                                                                            |
| `make run`                              | Run the controller from your host against the current cluster                                  |
| `make install` / `make uninstall`       | Apply / delete the CRD on the current cluster                                                  |
| `make deploy IMG=...` / `make undeploy` | Deploy / remove the controller on the current cluster                                          |
| `make docker-build IMG=...`             | Runs `make test`, then builds the image                                                        |

CI (`.github/workflows/build.yml`) runs `make setup` and `make test`, builds the image, then smoke-tests it on kind with `make deploy`.

Because `make test` and `make build` regenerate code and manifests first, check `git status` afterwards for regenerated files.

## Changing the CRD or RBAC

After any change to `api/v1/*_types.go` (fields or `+kubebuilder:` markers):

1. Run `make manifests` to regenerate the CRD in `config/crd/bases/`.
2. Run `make generate` to regenerate `api/v1/zz_generated.deepcopy.go`.
3. Commit the regenerated files in the same change as the type change.

Run `make manifests` too after changing the `+kubebuilder:rbac` markers in the controller; it regenerates `config/rbac/role.yaml`. Do not hand-edit the generated files to match. See the README section "Modifying the API definitions" and the [Kubebuilder book](https://book.kubebuilder.io/introduction.html).

## Formatting

- Go: `make fmt` and `make vet`.
- Everything else: a Husky pre-commit hook runs `lint-staged`, which applies Prettier to staged files (`package.json`). Run `npm ci` once so the hook is installed. Do not bypass the hook.

## Secrets and access tokens: stop and ask

This operator handles live secret material. The machine account access token lives in the Kubernetes Secret named by `spec.authToken.secretName` (under the key `spec.authToken.secretKey`), and the synced values are written into the Secret named by `spec.secretName`. The Dev Container forwards `BWS_ACCESS_TOKEN` from the host environment.

- Never put real access tokens, organization IDs or secret values in code, tests, samples, logs, `.env.example` or commits. Use placeholders such as `<Auth-Token-Here>`, as the README does.
- Stop and ask before changing how the auth token is read, how secret values are written to the Kubernetes Secret, or anything that could log secret values.
- Stop and ask before running `make install`, `make deploy`, `make undeploy` or `kubectl` commands against any cluster other than the local kind cluster.
- Report vulnerabilities as described in [SECURITY.md](../SECURITY.md).
